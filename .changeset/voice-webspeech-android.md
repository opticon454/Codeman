Voice dictation with the browser's own speech service no longer ends at the first pause, and a phone's mic button works on the first tap. The session used to end at the first finished phrase (a final result is only a pause in the speech), so on Android a person who said a word and drew breath found the microphone already off about two seconds in. A phrase now goes into the prompt and it keeps listening (Chrome and Edge on Android ignore `continuous` and end the recogniser at the first pause, so an engine that ends by itself is re-armed while the quiet window is still open, up to 40 times, and a quiet spell ending it after dictation is a normal end, not an error; and because Chrome on Android re-sends the whole running sentence as one "final" result on every update, the text is taken as the session's latest transcript and only what is new is inserted, instead of the sentence again each time); it ends on a tap or after 4 s of quiet after the last phrase (8 s to begin speaking, counted from when the engine reports it is listening), and nothing is inserted twice however it ends (direct mode appends only the new phrase, compose mode replaces the editor text with everything dictated so far). The "interim text stopped changing for 750 ms, call it final" rule is for iOS, where finals never arrive, and now applies only there. Also: no second microphone capture (`getUserMedia`, for the cosmetic level meter) is opened on Android, where it competes with the recogniser; every ending that was not the person's own tap now says why (`no-speech`, `aborted`, `audio-capture`, `service-not-allowed`, nothing heard); and the toolbar's tap-while-the-keyboard-is-up handling treats a focused terminal input as "keyboard up", because `visualViewport` detection can miss on Edge for Android, where the first tap on the mic took focus from the terminal (dropping the keyboard) and only the second reached the button.
